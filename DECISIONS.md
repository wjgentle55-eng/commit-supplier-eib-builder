# Decisions

Running log of choices made while building the Supplier EIB Builder, and why.
Status: **Locked** (agreed with Jack), **Default** (my call, open to change), **Proposed** (needs Jack's confirmation before the milestone that depends on it).

| ID | Date | Decision | Status |
|---|---|---|---|
| D-001 | 2026-10-29 | Repo is private `wjgentle55-eng/commit-supplier-eib-builder`. Commits are pushed through the GitHub web UI as the signed-in account. | Locked |
| D-002 | 2026-10-29 | The RAVN workbook is out of scope, including as a rule source. Validation rules come from brief section 6.6 plus the Conversion Workbook's Address Rules and Bank Rules tabs. | Locked |
| D-003 | 2026-10-29 | Vanilla JS (ES modules), no UI framework. Vite 8.3.4 + vite-plugin-singlefile 2.3.3 build one HTML file. Versions are pinned exactly and were all released at least two weeks before pinning. | Default |
| D-004 | 2026-10-29 | **The EIB is written by injecting rows into the template's sheet XML (JSZip), not by an ExcelJS round-trip.** The brief asked to verify ExcelJS first. It failed: ExcelJS expanded the template's 56 data validations into about 3 million per-cell entries in memory and wrote them back as 223 differently grouped validations, and it dropped the auto color on header borders. Injection keeps every package part except the sheet byte-identical, and keeps rows 1 to 5, `<cols>`, merged cells, and data validations in the sheet byte-identical too (see `tests/template-roundtrip.test.js`). ExcelJS stays in the project for the branded exception report, where we build the file from scratch. | Default |
| D-005 | 2026-10-29 | SheetJS is the official 0.20.3 release, downloaded from cdn.sheetjs.com and vendored at `vendor/xlsx-0.20.3.tgz` (sha256 `8dc73fc3b00203e72d176e85b50938627c7b086e607c682e8d3c22c02bb99fe8`), installed as `file:vendor/xlsx-0.20.3.tgz`. The npm registry only has 0.18.5, which has known advisories (prototype pollution, ReDoS). The one remaining `npm audit` item is a moderate `uuid` advisory inside ExcelJS; it affects a code path (`v3/v5/v6` with a caller buffer) neither library uses here. | Locked |
| D-006 | 2026-10-29 | npm needs `legacy-peer-deps=true` (in `.npmrc`) because npm 10's peer resolver crashes on vitest 5's optional browser peers. No runtime effect. | Default |
| D-007 | 2026-10-29 | The built page carries a strict Content Security Policy (`default-src 'none'`, `connect-src 'none'`, inline scripts and styles only, `data:`/`blob:` images). This makes "no network calls at runtime" enforced by the browser, not just by convention. | Default |
| D-008 | 2026-10-29 | EIB columns are keyed as `Area :: Field #occurrence`, with Area carried forward across blank row-2 cells. In v44.1 only one Area + Field pair repeats (`Web Address` in Web Address Data+, the second one being the `Web_Address_ID` reference). `src/eib/template-columns.json` snapshots all 411 columns and a test fails if the template headers change. | Default |
| D-009 | 2026-10-29 | Workbook columns ending in `+` are treated as multi-value even where row 2 doesn't say "multi" (`Classifications > Value+`, `Suppliers > Included Children+`, `Proposed Children+`). | Default |
| D-010 | 2026-10-29 | Value Mapping headers are matched tolerantly, so the workbook's "Workday Value" matches the brief's "Workday Value(s)". | Default |
| D-011 | 2026-10-29 | `Suppliers > Supplier Note` maps to `Note Data+ > Note Content`. | Default |
| D-012 | 2026-10-29 | Approval Status is `APPROVED` (Document_Status_ID), confirmed by Jack. Still editable per workspace in settings. | Locked |
| D-013 | 2026-10-29 | Address lines go on nested `Address Line Data+` rows with Type `ADDRESS_LINE_1` through `ADDRESS_LINE_4`. City goes to `Municipality`. Subregion and Submunicipality use the same nested Type pattern. | Locked |
| D-014 | 2026-10-29 | Communication usage `Type*` (Communication_Usage_Type_ID) defaults to `BUSINESS` for every address, phone, email, and web address, since the workbook doesn't collect it. | Locked |
| D-015 | 2026-10-29 | Supplier status writes to `Supplier Status Data+` with Row ID 1. `Proposed Supplier Status Data` is left blank. | Locked |
| D-016 | 2026-10-29 | Region IDs: bundle a standard ISO 3166-2 subdivision list at build time so regions resolve as Assumed (for example `USA-TX`) instead of Unresolved. | Locked |
| D-017 | 2026-10-29 | Related Worktags and classification choice columns take one reference ID type per column, so the ID type is chosen per export in workspace settings. Suppliers whose worktags need a different ID type get flagged to load in a separate file. | Locked |
| D-018 | 2026-10-29 | `Add Only` and `Submit` are left blank as submission plumbing. | Locked |
| D-019 | 2026-10-29 | Baseline Use For values: Billing, Remit To, Shipping, Procurement. Anything else is loaded per client as tenant values. | Locked |
| D-020 | 2026-10-29 | No hosted version and no login. Milestone 9 ships the single HTML file as a GitHub release asset (built by Actions). No GitHub Pages. | Locked |
| D-021 | 2026-10-29 | No sample tenant reference export yet. The tenant value loader is built around the 3-column format (Reference ID Type, Reference ID, Display Name) plus tolerant handling of common report shapes. | Default |
| D-022 | 2026-10-30 | Multi-value splitting: semicolons and line breaks always split. Commas split too, except before a legal-form suffix (Inc, LLC, Ltd, Corp, N.A., ...), so "601 RAVN Group, Inc" stays one company. Found in Jack's RAVN test workbook, where a plain comma split broke Restricted to Companies in two. | Default |
| D-023 | 2026-10-30 | A supplier name that appears on other tabs but not on the Suppliers tab still becomes a supplier record (so nothing is lost), flagged with an error to fix the spelling or add the row. A name on the Suppliers tab twice is merged and flagged as an error. | Default |
| D-024 | 2026-10-30 | Fixtures (`fixtures/`, built by `scripts/build-fixtures.mjs`) use only fictional data. Real client test files are never committed. | Locked |
| D-025 | 2026-10-30 | Loose tables: repeated supplier rows merge into one supplier, each row can add one record per section (address, email, bank account...), exact repeat records are dropped, and missing Account Labels are generated as ACCT1, ACCT2, ... | Default |
| D-026 | 2026-10-30 | Reference IDs: once tenant values are loaded for a type, only tenant matches count for that type. The baseline and the ID pattern are used only for types with no tenant values. A fuzzy hit is always just a suggestion. | Default |
| D-027 | 2026-10-30 | ISO country codes and currency codes are Workday-delivered and the same in every tenant, so a baseline hit for them counts as Matched, not Assumed. Regions stay Assumed, per D-016. | Default |
| D-028 | 2026-10-30 | Assumed IDs for delivered values: Checking = `DDA`, Savings = `SA`; Use For Billing/Remit To/Shipping/Procurement = `BILLING`/`REMIT`/`SHIPPING`/`PROCUREMENT`; US EIN = `USA-EIN`, US SSN or ITIN = `USA-SSN`; other tax ID types `<ISO3>-<pattern>`; everything else by pattern (`Net 30` -> `Net_30`). All Assumed until confirmed at the gate or matched to tenant values. | Default, verify in tenant |
| D-029 | 2026-10-30 | Tenant matching ignores case and whitespace only (brief 6.4). Baseline and synonym matching also ignore accents and punctuation (so "Haryāna" finds IND-HR). | Default |
| D-030 | 2026-10-30 | Possible duplicate vs Existing Suppliers: same name, a similar name (85%+ after dropping Inc/LLC/etc.), or the same tax ID. A matching bank account last 4 is added as a reason only alongside one of those, since 4 digits alone match too often. Warning only. | Default |
| D-031 | 2026-10-30 | **Row stacking (needs your sandbox load to confirm):** parent fields sit on the parent's first row, and the parent's Row ID repeats on every row its nested data uses (address lines, Use For values, an account's intermediaries and bank addresses). Groups at the same level are independent. Usage Data and Type Data each get Row ID 1. See `tests/golden/expected-eib-clean-fixtures.review.csv`. | Proposed |
| D-032 | 2026-10-30 | Address component Types: lines `ADDRESS_LINE_1..4`, Submunicipality `CITY_SUBDIVISION_1`, City Subdivision `CITY_SUBDIVISION_2`, Subregion `REGION_SUBDIVISION_1`. City goes to Municipality. | Proposed |
| D-033 | 2026-10-30 | Business Entity Name defaults to the Supplier Name when blank. | Default |
| D-034 | 2026-10-30 | Contact usage (Usage Row ID 1, Public, Type Row ID 1, Primary, Type `BUSINESS`, Use For) is written for addresses, phones, emails, and web addresses. Bank addresses get no usage block. | Default |
| D-035 | 2026-10-30 | Phones: Country ISO Code is the alpha-3 code (USA) and International Phone Code is the dialing code (1), both from the Lists tab. | Proposed |
| D-036 | 2026-10-30 | Classification values: one value goes to Field Text Value; several go to Field Multi Select Choice+ (one per row). | Proposed |
| D-037 | 2026-10-30 | The only header cells ever changed are row 4 Default Worktag (OD4) and Allowed Worktag (OI4), set to the Related Worktags ID type (D-017) when worktags are exported. Their style is kept. Everything else in rows 1 to 5 stays byte-identical. | Default, confirm |
| D-038 | 2026-10-30 | Duplicate name, tax ID, or bank account within the batch: the first supplier keeps it and later ones get the error, so the original stays clean. | Default |
| D-039 | 2026-10-30 | Bank Rules "Do Not Show" fields with a value are errors (brief 6.6). For US accounts this includes Name on Account, which affects 8 suppliers in the RAVN test file. | Default, confirm |
| D-040 | 2026-10-30 | EIN format (##-####### or 9 digits) is an error. An EIN prefix not on the IRS published list is only a warning, because that list changes. | Default |
| D-041 | 2026-10-30 | Exception report is client-facing: assumed-ID warnings (a Commit-side check) are left out, unresolved values are worded for clients, and bank account, IBAN, and tax ID values are masked to the last 4. | Default |
| D-042 | 2026-10-30 | Generated IDs use patterns with {date} {key} {n} {label}, set per workspace. Defaults: `ADDR-{date}-{key}-{n}`, `SBA-{date}-{key}-{n}`, `IBA-{date}-{key}-{n}`. | Default |
| D-043 | 2026-10-30 | The built file is about 2.6 MB (700 KB gzipped), mostly ExcelJS and the bundled reference data. Still one self-contained HTML file. | Default |
| D-044 | 2026-10-30 | Zero phones, emails, web addresses, or tax IDs is fine. When there are any, exactly one must be Primary. A supplier with no address gets a warning. | Default |
| D-045 | 2026-10-30 | Exports require a confirmation of every remaining assumed ID (confirm them, or tick "I've reviewed the assumed IDs"). Errors on any included supplier block the export. | Default |
